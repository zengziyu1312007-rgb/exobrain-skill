# 架构：外脑核心 + 方法论 + 日常工具

外脑是个人上下文与积累的入口，各个 Skill 是可以单独装卸的能力。实际记录与公开源码分开，不为安装模块复制个人资料。

| 层 | 责任 | 当前实现 |
|---|---|---|
| 外脑核心 | 认识使用者、约定范围、完成任务、积累与找回 | `my-exobrain` |
| 名人方法论 | 把不同人物的方法应用到同一组事实，比较分歧 | `exobrain-council`，24位方法卡、七个职能团 |
| 日常工具 | 处理具体任务，按平台或场景细分 | 账号安全 → `claude-account-safety` |

## 目录与依赖

`catalog.json` 是分类、版本与技能路径的唯一目录。所有可安装技能直接位于 `skills/<name>/`，每个都有自己的 SKILL.md、引用与脚本。层级分类写在目录中，不把一个技能嵌在另一个技能里面，便于独立安装、更新和分发。

外脑核心不依赖可选模块。智囊团和账号安全既可使用当前输入，也可在用户获准的外脑范围内读取必要背景；没有安装核心时仍可单独处理任务，不假称记得历史。技能不把自身目录当成个人记录目录。

分类不是强制工作流，也不是自动执行系统。普通记录不启动完整智囊团；账号错误不要求先做外脑访谈；只有问题需要时才联合使用。未安装的模块可以说明位置，不擅自联网安装。

## 名人方法论如何继续扩展

目前24位人物由一个智囊团 Skill 和方法卡承载，支持指定单个人物；不把同一份内容复制成24个空壳技能。人物资料中保留来源及核验状态，不能把产品归纳写成人物原话。

当某种方法具有独立流程、参考材料和明确触发场景时，可新增独立 Skill 并归入 `methods`。共用来源只维护一份，独立包必须包含其运行所需资源。只增加实际可用能力，不在安装目录放待开发占位技能。

## 日常工具如何继续扩展

`daily / account-safety` 是通用账号安全分类，Claude 是其中一个平台模块。以后其他平台各自新增 `skills/<platform>-account-safety/`，在 `catalog.json` 使用同一分类，保留各平台当前的官方来源与排错步骤。

不把 Claude 的限额、登录界面或申诉规则推广到所有平台。账号操作与用户任务授权保持一致，读取报错不代表获准更改密码、撤销密钥或提交申诉。

## 新模块的维护

1. 增加完整技能目录和明确的触发描述。
2. 登记 `catalog.json`，更新技能目录与安装示例。
3. 检查独立解压后的资源链接、安装保护和必要脚本。
4. 发布时由打包器按目录自动生成单技能 ZIP 与完整项目 ZIP。

个人背景、客户数据、凭证与实际账号事件始终不进入本公开项目。
