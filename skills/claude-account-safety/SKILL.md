# Claude 账号安全

归属：日常工具 → 账号安全 → Claude。可独立使用；已有外脑只读取用户获准的相关记录，不复制私人账号资料到技能目录。

## 先分清问题

先依据用户给出的产品（Claude聊天、Claude Code或API）、错误原文和发生时间分类。脱敏截图即可，不索取密码、验证码、Cookie、Session、完整卡号或API密钥。缺信息时只补问会改变排查方向的部分。

| 情况 | 读取 |
|---|---|
| 注册、地区和支付资格 | [账号与地区](docs/01-账号注册合规.md) |
| 页面打不开、登录与网络问题 | [网络与登录](docs/02-网络环境管理.md) |
| 用量上限、API错误或重试 | [使用与限额](docs/03-使用规范.md) |
| 内容政策问题 | [政策入口](docs/04-内容合规边界.md) |
| 无法判断的异常 | [异常自查](docs/05-异常自查清单.md) |
| 明确受限、需要官方处理 | [申诉与恢复](docs/06-申诉与恢复.md) |
| 工作、个人与团队账号 | [多账号管理](docs/07-多账号合规管理.md) |

## 排查与输出

1. 区分已知症状、可能原因与尚未核实的信息。先查服务状态与错误说明，不把所有问题都判成封号。
2. 先给最有辨识力的下一项检查；依据结果继续。API 401、429、529分别检查鉴权、限流与服务过载，不能仅凭状态码断言账号被封。
3. 登录、订阅、服务地区与申诉路径会变化，使用对应文档的官方来源核对当前页面，注明查阅日期。查不到就明确未知，不编按钮、等待时长或解封概率。
4. 明确受限时提供当前官方申诉入口，按真实事实起草材料；无需等完所有自查或固定天数才联系支持。只有用户明确要求发送时才提交。
5. 如需留档，按外脑已有授权保存脱敏的症状、检查结果、处理动作和后续状态；凭证不写入记录。只聊不记时不落盘。

不保证不会封号或申诉成功；不推断未公开的风控评分、设备阈值或“养号”规则。不提供规避地区、身份或封禁限制的方法。涉及改账号设置、撤销密钥、取消订阅与发送申诉，分别遵守用户授权；描述自查不等于获准执行这些操作。

需要定期检查时用[账号保护清单](checklists/账号健康自查.md)，发生问题时用[异常应急流程](checklists/异常应急流程.md)。这些清单不提供账号风险评分。
